# review-arbiter — свод раунда 1 (Consilium, ревью репозитория world_agents)

Входы: contract-reviewer (файл), adversarial (сообщением), reverse-spec-reviewer (сообщением, с пометкой о частичном загрязнении реконструкции автоподгруженным индексом памяти — его совпадения не использованы как независимое подтверждение, расхождения проверены по артефакту). Допрос ревьюеров недоступен (портируемая модель) — недостающее помечено, не запрошено.

## ВЕРДИКТ: ВЕРНУТЬ АВТОРУ

Один blocker, четыре major, шесть minor. Все замечания ниже проверены арбитром по указанным местам артефакта.

## Blocker

### 1. Правило носителя вопроса циклично; сквозной пример нарушает его букву
- Где: TEAM.md:111-117, пример TEAM.md:152-157; тот же дефект larrey.md:170-178.
- Воспроизведение: «носитель — первый несрезанный из базы фазы» определим только ПОСЛЕ отрезов, а правило «носитель не отрезается» применяется ВО ВРЕМЯ отрезов. До отрезов первый несрезанный базы A — suntzu; пример режет suntzu и объявляет носителем hamming. Либо пример нарушает правило (носитель срезан), либо защита тавтологична (носителем задним числом называется тот, кто уцелел). В вырожденном случае (фаза A + 4 триггера = 7 кандидатов, лимит 4) буквальное чтение опустошает базу: носителя нет, состав нелегален по TEAM.md:114, легального хода правило не даёт.
- Схлопнуто: adversarial major-1 (единственный источник; contract-reviewer C3 «покрытие взаимно полное» не опровергнут — он сверял таблицы и description, семантику правил не проверял; конфликт вердиктов разрешён в пользу adversarial по проверке текста).
- Минимальный фикс: переформулировать однозначно, например «база режется по своему порядку, но последний остающийся базовый не режется — он носитель; дальнейшие ёмкостные отрезы переходят на триггерных», и синхронизировать larrey.md; пример тогда требует правки (носитель — munger) либо правило носителя при фазовом вопросе задаётся смыслом вопроса, а не позицией в порядке отреза.

## Major

### 2. Сквозной пример пропускает обязательную паузу правила 2 и опирается на неписаное снятие «непокрыто»
- Где: TEAM.md:118-124 (правило 2) против TEAM.md:146-174 (пример).
- Воспроизведение: в примере есть ёмкостный отрез (suntzu), но нет ни показа владельцу, ни пометки «режим автономный»; по правилу 2 отрезанный обязан уйти в «непокрыто» свода — в вердикте шага 4 suntzu в «непокрыто» нет, потому что он вернулся передачей такта 2. Случай «ёмкостно отрезанный вернулся тактом 2 — закрывает ли это его „непокрыто“» правилами не описан.
- Источник: adversarial major-2. Фикс: строка в примере (пауза или «автономный режим») + строка в правиле 2 о возврате тактом 2.

### 3. Словарь вердиктов review-arbiter не покрывает фазы A/B — пример TEAM.md выносит вердикт вне словаря
- Где: review-arbiter.md:24-28 против TEAM.md:169-174.
- Воспроизведение: закрытый словарь (ВЕРНУТЬ АВТОРУ / ПРИНЯТО [С ЗАМЕЧАНИЯМИ] / ПРОВЕРКА НЕ ПРОВЕДЕНА) написан под готовую работу; вердикт примера «не начинать до закрытия…» — вне словаря, обязательной строки «Раунд N из 2» в примере нет. Приоритизация review-arbiter.md:20 тоже кодо-центрична.
- Уточнение арбитра (часть находки ослаблена): утверждение adversarial «вердикты A-фазы по букве отсева review-arbiter.md:12 — шум» неверно: отсев требует отсутствия «сценария ИЛИ места в артефакте», а фазовые вердикты (hamming, suntzu) опираются на места во входе — по букве выживают. Ядро (словарь) подтверждено.
- Источник: adversarial major-3 (замечание о спеке самого арбитра; подтверждаю против себя). Фикс: расширить словарь фазовыми вердиктами или объявить его словарём фазы C с правилом для A/B.

### 4. Счётчик «двух командных раундов» не имеет носителя
- Где: TEAM.md:141-144, larrey.md:201-208, формат larrey.md:293-294.
- Воспроизведение: лимит хранится «правилом арбитра», но арбитр зовётся только при ≥2 отчётах; цикл «правки → триаж по дельте → один агент → свода нет» не инкрементирует ничей счётчик и повторяем неограниченно. По словарику TEAM.md:45-46 раунд включает свод — цикл без свода формально даже не раунд. larrey пишет «раунд N из 2» в roster, но источник N не сшит. В портируемой модели (арбитр получает всё одним входом) N обязан приходить извне — от кого, не сказано.
- Источник: adversarial major-4. Фикс: назначить носителя счётчика (вызывающий передаёт N на вход и larrey, и арбитру) одной строкой в TEAM.md.

### 5. Портируемость: позиция ROADMAP не выполнена, раздел TEAM.md — непроверенная инструкция с конкретной дырой
- Где: ROADMAP.md:30, TEAM.md:176-188.
- Воспроизведение (contract-reviewer, проверено): следа прогона в другом harness нет ни в файлах корня, ни в 46 коммитах (`git log --all --oneline | grep -i -e harness -e portab` → только 302ad7a, добавляющий саму строку ROADMAP). По собственному критерию ROADMAP позиция не закрыта. Дыра механизма (adversarial): «изоляция — порядком» в harness без субагентов работает только при свежем контексте на каждого ревьюера — иначе последовательный исполнитель держит чужие отчёты в контексте и по TEAM.md:125-127 «становится копией»; условие свежего контекста в разделе не названо.
- Схлопнуто из всех трёх отчётов (contract №1, adversarial major-5, reverse-spec «пропущено major»). Самая точная рамка — у reverse-spec: локальная подмена в разделе инфраструктуры — заявленная работа (прогон goldratt + запись дельты) заменена незаявленной (протокол Consilium).
- Фикс: минимальный шаг из самого ROADMAP — один прогон goldratt во втором harness + файл с дельтой; в TEAM.md:178-182 добавить условие «свежий контекст на вызов».
- `Требует решения человека`: признать ли протокол Consilium одобренным расширением scope и внести в ROADMAP задним числом — или это отклонение от заявленного (одна строка решения владельца).
