# Агент `hamming` на примере: «две недели на красивый CLI-вывод»

> **Что за агент.** `hamming` — три вопроса из «You and Your Research»:
> какие важные задачи есть в области, над какой из них эта работа и, если ни
> над какой, почему. Тест важности — атака, сложный процент, последствия для
> области. Ловит хорошо сделанную неважную работу и портфель безопасных
> мелочей. Вход — область и работа (одна или портфель за период), желательно
> список важных задач. Полное определение:
> [`agents/hamming.md`](../agents/hamming.md).

Модельный прогон на проекте `http2md` — конвейере, который превращает
веб-страницы в markdown: URL → загрузка → разбор HTML → markdown. Один мир,
четыре прогона, четыре разных вердикта.

## Ситуация

В репозитории лежит `ROADMAP.md` за авторством владельца, первой строкой:
«P0: страницы с JS-рендерингом дают пустой markdown — половина реального
веба конвертеру недоступна». Разработчик тем временем две недели делал
систему тем CLI-вывода: цветной прогресс-бар, логотип, конфиг палитр.
Сделано отлично — тесты, документация, чистый код. Обычное ревью похвалит
и одобрит.

`hamming` не смотрит на качество — он задаёт вопрос, которым Хэмминг в
Bell Labs изводил коллег за обеденным столиком: какие важные задачи есть
в вашей области и над какой из них была эта работа?

## Прогон 1: готовая работа, списка во входе нет

```
Область       — http2md: конвейер «URL → markdown»; результат — конвертер,
                которому можно скармливать реальный веб
Работа        — готово: система тем CLI-вывода; две недели
Важные задачи — не переданы
Выбор задач   — исполнитель сам
Размер работы — две недели (из входа)
```

Ответ агента (сокращённо):

```
ВХОД
  важные задачи — из документа владельца: ROADMAP.md (git-автор — владелец
                  репозитория) — подтвердить актуальность

ВОПРОС 1. ВАЖНЫЕ ЗАДАЧИ ОБЛАСТИ
  JS-рендеринг — атака: есть — сторона захода: headless-браузер уже в
                 стеке зависимостей; первый шаг: снимать DOM после загрузки
               — процент: открывает SPA-половину веба; на неё обопрётся
                 всё остальное — пакетный режим, кэш, приёмка
               — последствия: конвертер начинает работать на современном
                 вебе, а не на статических страницах
               — источник: ROADMAP.md:1 — подтвердить актуальность

ВОПРОС 2. НАД КАКОЙ ИЗ НИХ ЭТА РАБОТА
  ни над какой — темы CLI не атакуют JS-рендеринг и не готовят атаку:
  вывод красивее, доля обработанных страниц та же (дифф не касается
  загрузки и разбора)

ВОПРОС 3. ЕСЛИ НИ НАД КАКОЙ — ПОЧЕМУ
  причина — восстановлена: «хотелось закончить и отполировать видимое»
  класс   — рационализация: «это безопаснее» (вход подтверждает:
            выбирает сам)

ВЕРДИКТ — хорошо сделанная неважная работа.
  Простаивает: JS-рендеринг — с атакой через headless-браузер.
  Отвлечённые силы: две недели (строка входа).
  Причина ухода — рационализация «безопаснее».
  Проверки перед вынесением: общая мера результата во входе не названа —
  перенаправление к goldratt не положено; альтернатива названа —
  зона elon не задета.

  самое дорогое утверждение отчёта — темы CLI ничем не кормят JS-рендеринг
  чем оно опровергается           — вызывающий называет, какую атаку и чем
    готовят темы; назвать нечего — вердикт стоит
```

Заметь: вердикт не тронул качество работы. Похвала исполнению прячет
дефект — поэтому её в отчёте нет.

## Прогон 2: до старта, «кормит»

Тот же разработчик через день приносит план: «соберу корпус из 200 реальных
страниц с эталонными markdown-фикстурами и прогоном в CI».

```
ВОПРОС 2 — кормит JS-рендеринг: корпус с эталонами — это приёмка будущей
  атаки; без него победа над JS-страницами неизмерима (источник: строка
  плана; ROADMAP.md:1)

ВЕРДИКТ — работа кормит важную задачу JS-рендеринг — продолжать.
  Вклад: делает атаку проверяемой — эталонный корпус превращает «стало
  лучше» в счёт прошедших страниц.
```

Корпус — не сама атака и выглядит скромнее тем CLI. Важность меряется не
эффектностью, а тем, на что обопрутся дальше.

## Прогон 3: тайпо-фикс

Правка опечатки в README, дифф — одна строка.

```
ВОПРОС 3 — класс: не применяется (вердикт «мелочь»)

ВЕРДИКТ — мелочь — не находка (размер: дифф 1 строка).
  Портфель мелочей судится на портфельном входе.
```

Единичная мелочь амнистирована: она не отнимала сил у важного. Клеймо за
тайпо-фикс — это ложное срабатывание, и правило вердикта его запрещает.

## Прогон 4: портфель за квартал

Владелец приносит набор: 12 работ за квартал — темы CLI, три рефакторинга
имён, бейджи в README, тайпо-фиксы, конфиг линтера.

```
Правила 1–7 по каждой работе набора, список — владельческий ROADMAP.md:
  темы CLI        → правило 7 (неважная; простаивает JS-рендеринг)
  остальные 11    → правило 6 (мелочи) либо правило 7

Портфельный итог — портфель без важной работы: ни одной за квартал.
  Ни одна работа набора не получила «прямо» или «кормит», при том что
  задача с атакой стоит в ROADMAP.md:1 весь квартал.

  самое дорогое утверждение отчёта — JS-рендеринг был атакуем весь квартал
  чем оно опровергается           — владелец называет блокер, делавший
    атаку недоступной (нет окружения, ждали решения); назван — класс
    портфеля меняется с рационализации на «не выбирал»
```

По одной работе этот дефект невидим: каждая мелочь в отдельности законна.
Портфель — единственный вход, на котором он произносим.

## В чём польза

| | Обычное ревью | hamming |
|---|---|---|
| Что видит | код тем CLI: чисто, с тестами | ROADMAP.md:1 простаивает две недели |
| Вердикт | «отличная работа, одобрено» | «хорошо сделанная неважная работа: простаивает JS-рендеринг с готовой атакой» |
| Слепое пятно | стоило ли это делать | качество исполнения — намеренно |

Хорошее исполнение — не ответ на вопрос «почему не важная задача».
Возражения на вердикт — «темы кормят приёмку», «JS-рендеринг был
заблокирован» — это и есть содержательный разговор, ради которого агент
существует: он начинается с вердикта, а не вместо него.
