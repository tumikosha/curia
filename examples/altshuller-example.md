# Агент `altshuller` на примере: «снизим параллельность вдвое»

> **Что за агент.** `altshuller` — ядро АРИЗ: функция вместо механизма,
> идеальный конечный результат как линейка (функция выполняется, механизма
> нет), противоречие «улучшая A, ухудшаем B» с независимыми критериями и его
> разрешение разделением по координате — во времени, в пространстве, по
> условию, между системой и частями. Ловит компромисс вместо разрешения
> (критерий куплен, конфликт жив) и симптомное решение. Вход — боль/задача,
> желательно решение. Полное определение:
> [`agents/altshuller.md`](../agents/altshuller.md).

Модельный прогон на проекте `http2md` — конвейере «URL → markdown».
Одно противоречие, три прогона.

## Ситуация

Пакетный прогон 500 URL с 16 воркерами: быстро, но сервера банят за
частые запросы — прогон падает. Предложение в PR: «снизить
параллельность до 4 — и скорость терпимая, и баны реже». Обычное ревью
одобрит: взвешенно, аккуратно.

## Прогон 1: компромисс

```
ФУНКЦИЯ — пакет из 500 URL скачивается быстро и без банов
ИКР — сервера сами отдают страницы с максимальной скоростью, которую
  разрешают; механизма торможения нет

ПРОТИВОРЕЧИЕ (направленная связь есть: больше параллельность —
  быстрее прогон И чаще баны, при любых порогах)
  требование A — прогон ≤ 10 мин — критерий: SLO пакетного режима
                 (README:22) — источник независим от решения
  требование B — ноль банов за прогон — критерий: тикет #83 «прогон
                 падает» — источник независим

РАЗБОР РЕШЕНИЯ (воркеры 16 → 4)
  требование A — ЧАСТИЧНО: прогон ~25 мин, SLO нарушен (замер в PR)
  требование B — целиком: банов нет на тестовом прогоне
  → оба живут в одной координате (глобальная параллельность),
    A куплен

ВЕРДИКТ — компромисс — конфликт жив: требование A частично.
  Перебор координат (мой, в этом отчёте):
  - в пространстве: параллелить ПО ДОМЕНАМ — 16 воркеров, но ≤1
    запроса на домен одновременно; баны считает домен, скорость —
    пакет; ПРИМЕНИМА, даёт оба целиком
  - во времени: ночной прогон — баны не исчезают, НЕ РЕШАЕТ
  - по условию: медленно только для банящих доменов — применима как
    дополнение (адаптивный backoff по 429)
  - система-части: каждый воркер вежлив, пул агрессивен — это и есть
    подоменная схема другими словами
  Программа: принять координату «пространство», обосновать цену или
  предъявить выбор решающего.

  самое дорогое утверждение отчёта — банит домен, а не общий объём
    трафика конвейера
  чем оно опровергается — прогон 16 воркеров по 16 разным доменам:
    баны есть → банит объём, координата не сработает
```

Компромисс не заклеймён голословно: перебор координат приложен, у
вызывающего три выхода.

## Прогон 2: повторный вход — разделение принято

Реализовано: 16 воркеров, очередь по доменам, ≤1 запрос на домен.

```
РАЗБОР РЕШЕНИЯ
  требование A — целиком: прогон 8 мин (замер) — SLO выполнен
  требование B — целиком: ноль банов за три прогона
  координаты — A в целом пакете, B на каждом домене: разные

ПЕРЕБОР ПЯТИ (что ухудшил сам приём)
  ресурс — цел: те же 16 воркеров
  сложность — цел: очередь по доменам — 30 строк, эксплуатация
    не выросла
  латентность — цел (SLO выполнен), свежесть — цела, безопасность —
    цела

ВЕРДИКТ — противоречие разрешено — приём: разделение в пространстве
  (по доменам). Оба целиком.
  Расстояние до ИКР: механизм добавлен — доменная очередь; функция
  достижима без — если сервера отдают Retry-After, очередь заменяется
  честным ожиданием заголовка (ближе к «сервер сам говорит скорость»).
```

## Прогон 3: соседний вход — «снято при порогах»

Тот же конвейер, вопрос про кэш: TTL=60с, SLO p99<100мс (README) и
свежесть ≤60с (тикет #91). Направленная связь есть, но оба независимых
критерия выполнены в лоб.

```
ВЕРДИКТ — снято при заданных порогах — разделение не потребовалось.
  Триггер пересмотра: требование свежести жёстче 60с вернёт конфликт —
  тогда координаты из перебора: по условию (свежесть только
  залогиненным — если тикет сузит объём).
```

А вот если бы SLO не было и критерии восстанавливались из константы
TTL самого кэша — это эхо, не критерий: вердикт был бы «симптомное
решение — назвать независимые критерии», а не «снято».

## В чём польза

| | Обычное ревью | altshuller |
|---|---|---|
| «Снизим вдвое» | «взвешенно, одобрено» | компромисс: SLO куплен, конфликт вернётся |
| Что предлагает | принять или отклонить | координату, где оба требования целиком |
| Линейка | «лучше, чем было» | расстояние до ИКР: что добавлено и без чего можно |

Конфликт, купленный компромиссом, возвращается с ростом; конфликт,
разведённый по координатам, закрыт — и у решения появилась линейка,
на которой ноль — «система сама».
