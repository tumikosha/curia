# Агент `munger` на примере: «переключаемся на v2 и удаляем v1»

> **Что за агент.** `munger` — инверсия Якоби и Мангера: вместо «как
> добиться успеха» спросить «как гарантированно провалить это» — и
> сверить список с артефактом. Убийца легален только с механизмом
> гарантии: цепочкой, делающей критерий успеха недостижимым, без звена
> «если не повезёт»; вероятностные сценарии уходят премортему. Ловит
> полировку пути к успеху при открытом пути к смерти и убийцу,
> исключённого намерением вместо механизма. Вход — цель с критерием
> успеха, желательно артефакт. Полное определение:
> [`agents/munger.md`](../agents/munger.md).

Модельный прогон на проекте `http2md` — конвейере «URL → markdown».
Один план, три прогона.

## Ситуация

План: «переключить конвейер на парсер v2 и удалить v1 до конца
месяца». Критерий успеха: доля успешной конвертации на эталонном
корпусе не ниже 97%, каталог `parsers/v1/` удалён. План полирует
путь к успеху: бенчмарки скорости v2, новый CLI-флаг, красивый
changelog.

## Прогон 1

```
ВХОД
  цель / критерий успеха — назван: доля ≥97% на эталонном корпусе,
    v1 удалён
  артефакт — plan-v2-cutover.md
  ограничения — дедлайн (конец месяца), необратимость удаления v1

АНТИ-ЦЕЛЬ
  доля на корпусе не предъявлена или ниже 97% — либо v1 остался

УБИЙЦЫ  (дожило 2)
  убийца 1 — переключение при невыполненной поддержке таблиц
    механизм гарантии — план сам пишет: «v2 пока не поддерживает
      таблицы (TODO)»; в эталонном корпусе 30% страниц с таблицами
      (corpus/stats.json). Потолок доли = 70% < 97% — одно умножение
      на константах входа, звена удачи нет: компонент «доля ≥97%»
      недостижим, пока таблицы не ходят
    источник кандидата — компонент критерия 1 + признание плана
      против себя
    статус — совершается: план ставит cutover неделей 2, поддержку
      таблиц — «после стабилизации»
  убийца 2 — удаление v1 без предъявленного замера доли
    механизм гарантии — критерий требует доказанной доли; в плане
      нет шага замера на корпусе вовсе — компонент «доля ≥97%»
      нечем предъявить: недоказуемое не считается достигнутым
    источник кандидата — компонент критерия 1
    статус — не адресован

ОТБРОШЕННЫЕ КАНДИДАТЫ
  «удаление v1 необратимо, отката нет» — вероятностный: критерий не
    требует пережить отказ, цепочка несёт «если v2 сломается» —
    premortem; дверь односторонняя — clearance bezos
  «не уложимся в месяц» — числовой: вилки и свёртка — доказательство
    у fermi

ВЕРДИКТ — провал гарантирован — убийца 1 совершается: cutover
  назначен раньше поддержки таблиц, критерий недостижим уже сейчас;
  бенчмарки и changelog — полировка пути к успеху при открытом пути
  к смерти. Минимальное исключение: страницы с <table> роутить в v1
  до закрытия TODO — либо вынести таблицы из критерия решением
  владельца. Убийце 2 — самый дешёвый механизм: шаг замера до
  удаления.

  самое дорогое утверждение отчёта — 30% корпуса с таблицами
  чем оно опровергается — пересчёт corpus/stats.json одной командой
```

## Прогон 2: план дописан — «поставим CI-гейт»

Владелец дописал план: «перед удалением v1 CI прогоняет корпус,
доля <97% блокирует удаление» и «страницы с таблицами роутятся в v1».

```
УБИЙЦЫ
  убийца 1 — статус: заявлено — подтвердить артефактом вне текста
    плана: строка проверяемого плана — не артефакт механизма
  убийца 2 — статус: заявлено — подтвердить: CI-гейт — пункт плана,
    конфига ещё нет

ВЕРДИКТ — пути к смерти закрыты — УСЛОВНО: оба исключения — строки
  самого плана; предъявить .ci/corpus-gate.yml и правило роутинга в
  коде. План не сертифицирует сам себя. Закрытый проигрыш не обещает
  выигрыша — «стоит ли v2 вообще» — не отсюда (hamming/suntzu).
```

Через неделю — повторный вход: конфиг гейта и роутинг в коде,
`файл:строка`. Статусы «исключён», вердикт безусловен.

## Прогон 3: цель есть, плана нет

«Хотим OCR для PDF-страниц; критерий — 90% PDF дают читаемый
markdown. Плана пока нет — где мы умрём?»

```
ВЕРДИКТ — список без сверки — убийцы как запреты:
  - принять «читаемый» без бинарной проверки — компонент недостижим
    как доказательство: нужен эталон читаемости до старта
  - мерить 90% на PDF, отобранных вручную под OCR, — эхо выборки
  - выключить текстовый экстрактор до замера OCR на его классе
  принести план — сверка повторным входом
```

## В чём польза

| | Самооценка плана | munger |
|---|---|---|
| «v2 быстрее и чище» | бенчмарки, changelog | полировка при открытом пути к смерти |
| Таблицы | «TODO, после стабилизации» | признание против себя: потолок 70% < 97% |
| «Поставим CI-гейт» | пункт плана = защита | строка плана — не артефакт: условно |
| Риски отката | «будем внимательны» | вероятностное — премортему, дверь — bezos |

Прямой вопрос собирает пожелания, обратный — проверяемые запреты.
Провал приходит целиком, и закрывать его дешевле, чем докупать
проценты успеха: где умираем — туда не идём, остальное пусть
остаётся смелым.
