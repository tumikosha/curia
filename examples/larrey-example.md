# Агент `larrey` на примере: «перепишем парсер на Rust?»

> **Что за агент.** `larrey` — триаж ревью, по имени хирурга
> Наполеона, изобретателя сортировки раненых по профилю раны, а не
> по чину. Не судит артефакт и не запускает агентов — назначает:
> минимальный состав ревьюеров (≤4), вход каждому, порядок, свод
> через `review-arbiter`; исполняет вызывающий. Ловит «все на всё»,
> «не того специалиста» и «хор без свода». Протокол команды —
> [`TEAM.md`](../TEAM.md). Полное определение:
> [`agents/larrey.md`](../agents/larrey.md).

Модельный прогон на проекте `http2md` — конвейере «URL → markdown».
Три входа.

## Прогон 1: фаза A, ёмкостный отрез

Вход: «хотим переписать парсер на Rust: в 5 раз быстрее, выкинем
питоновский код; месяц работы. Стоит ли?»

```
ВХОД
  артефакт/намерение — переписывание парсера на Rust
  вопрос вызывающего — «стоит ли» → фаза A
  повторный вход — нет

ROSTER — такт 1 (параллельно, изолированно; ≤4)
  hamming — носитель вопроса «стоит ли» (вне конкурса) —
    вход: намерение + список важных задач области, если есть
  munger  — база A — вход: цель с критерием «в 5 раз быстрее»
  fermi   — триггер: числа «в 5 раз» и «месяц» — вход: числа и
    против чего мерить
  chesterton — триггер: «выкинем питоновский код» — удаления —
    вход: что удаляется и кто на это опирается
  замещения — нет
  отрезаны — suntzu: ёмкостный отрез — лимит 4, позиция 1 в
    порядке базы A

СВОД
  review-arbiter — после всех отчётов

ТАКТ 2  (≤2; такта 3 нет)
  исполнять: вероятностные кандидаты munger → premortem;
  «замер недоступен» fermi → suntzu
  остаток — «непокрыто — отдельным вызовом по решению владельца»

  самое дорогое утверждение отчёта — фаза A по вопросу «стоит ли»
  чем оно опровергается — строка входа, показывающая, что работа
    уже начата (тогда фаза B и другой состав)
```

## Прогон 2: юрисдикционный вопрос с триггером

Вход: «выключаем поддержку старых конфигов в следующем релизе —
какая это дверь?»

Вопрос совпадает с юрисдикцией `bezos` — но вход несёт детектируемый
триггер: выключение — удаление, на которое могли опереться →
`chesterton`. Триггеры бьют формулировку: вход не одиночный.

```
ROSTER — bezos (носитель вопроса, первым) + chesterton (триггер:
  удаление); база фазы не добирается — вопрос узкий
СВОД — review-arbiter: отчёта два
```

## Прогон 3: фаза неопределима

Вход: «вот план-док миграции кэша» — без вопроса; из дока не видно,
начата ли работа.

```
ВЕРДИКТ — вопрос задан — roster отложен:
  «работа не начата, идёт или предъявлена готовой?»
```

Ответ вызывающего «не начата» — легальный повторный вход: фаза A,
триаж продолжается. Ответа нет и во втором заходе — презумпция C
с пометкой «подтвердить».

## В чём польза

| | Без триажа | larrey |
|---|---|---|
| Состав | «позовём всех» — 19 отчётов | ≤4 профильных, отрезанные поимённо |
| Вопрос вызывающего | может утонуть в хоре | носитель вне конкурса — судится всегда |
| Удобная формулировка | «это просто вопрос про дверь» | триггеры бьют формулировку |
| Конфликты отчётов | вызывающий разбирается сам | review-arbiter — один вердикт |

Сортировка по ране, а не по чину: каждый вход встречает ровно те
вопросы, которыми задет, судьи работают молча и параллельно, а
вызывающий получает один вердикт — не хор.
