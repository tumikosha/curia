# Агент `goldratt` на примере: «давайте ускорим парсер»

> **Что за агент.** `goldratt` — ревью по пяти шагам фокусировки Голдратта:
> найти ограничение системы → выжать из него максимум → подчинить остальное →
> расширить → вернуться к шагу 1. Ловит локальное улучшение вне узкого места —
> работу, сделанную хорошо, но не двигающую меру результата. Вход — система с
> целью, изменение и мера результата (без меры — отказ). Полное определение:
> [`agents/goldratt.md`](../agents/goldratt.md).

Реальный прогон на проекте `http2md` — конвейере, который превращает
веб-страницы в markdown: URL → загрузка через Playwright → разбор HTML →
markdown.

## Ситуация

Разработчик предлагает: «Парсер написан неоптимально — перепишу его
эффективнее». Звучит разумно: код действительно можно ускорить, работа
понятная, результат измерим. Обычное ревью оценит качество переписанного
парсера и одобрит.

## Вход для агента

Контракт входа — три элемента:

```
Система   — http2md: конвейер URL → HTML → markdown; цель — обрабатывать страницы
Мера      — время полного цикла обработки одной страницы
Изменение — переписать парсер (разбор HTML) эффективнее
```

## Что ответил агент (сокращённо)

```
ПОРЯДОК: нарушен — улучшение стадии предложено без поиска ограничения.

ШАГ 1. ОГРАНИЧЕНИЕ
  ограничение — стадия fetch: правила ожидания Playwright
  тип         — правило (не ресурс!)
  признаки    — задержки зашиты в код детерминированно:
    - новый Chromium на каждую страницу (~0.3–1 с)
    - дефолт networkidle: +0.5 с минимум, до 30 с на шумных сайтах
    - автоскролл 100 px / 100 мс: 1 с на каждые 1000 px высоты
    - безусловный wait_for_timeout(1000): +1 с всегда
    Парсер замерен: 11 мс на типичной странице, 87 мс на большой.
    Fetch ≥ 2 с минимум, типично 3–35 с. Парсер — меньше 1 % цикла.
  опровергающая проверка — perf_counter вокруг fetch и md() на 10 реальных
    URL; ожидание: fetch ≥ 95 % цикла.

ШАГ 2. ВЫЖАТЬ — не исчерпано; четыре бесплатных резерва на fetch:
  убрать безусловную секунду, сменить дефолт networkidle, ускорить
  автоскролл, переиспользовать браузер (async-путь уже так делает).

ШАГ 4. РАСШИРИТЬ — недопустимо: шаг 2 не исчерпан.

ВЕРДИКТ — работа вне ограничения; вклад в меру: доли процента.
  Парсер занимает 11–87 мс из цикла 2–35 с — даже 10-кратное его
  ускорение сдвинет меру меньше чем на 0.5 %.
  Направить работу на правила ожидания fetch: бесплатные ~2 с/страницу
  минимум, до 30 с на шумных сайтах.
```

## В чём польза

| | Обычное ревью | goldratt |
|---|---|---|
| Что оценивает | качество переписанного парсера | вклад работы в меру результата |
| Вердикт | «код стал лучше, одобрено» | «мера не сдвинется: работа не в узком месте» |
| Итог | неделя работы, −50 мс на цикле в 10 с | час правок в fetch, −2…30 с на том же цикле |

Дефект «хорошая работа не в том месте» невидим для обычного ревью, потому
что обычное ревью оценивает изменение само по себе. `goldratt` сравнивает
его с ограничением системы — и возвращает работу туда, где она меняет
результат.

Заодно агент не поверил себе на слово: он **замерил** парсер (11–87 мс),
а самое дорогое утверждение отчёта снабдил опровергающей проверкой —
если тайминг на 10 реальных URL покажет md() > 5 % цикла, отчёт
пересматривается.

## Контрольный пример: вход без меры

Тот же вопрос, но мера результата не названа:

```
Система   — http2md: конвейер веб-страницы → markdown
Изменение — ускорить парсер
Вопрос    — это узкое место? стоит ли этим заниматься?
```

Ответ агента — **отказ**, а не отчёт:

```
ОТКАЗ — мера результата не названа; отчёт не выдаётся.
Определить одно из: страниц/час end-to-end либо секунд на страницу,
плюс текущий замер. Выдумывать меру самому мне запрещено.
```

Это защита от главного провала LLM-ревьюеров — уверенных выводов из
воздуха. Без меры результата слово «улучшение» неопределимо, и агент
скорее остановит разбор, чем сочинит его.

## Как позвать

Агент установлен симлинком в `~/.claude/agents/goldratt.md`. В сессии
Claude Code:

> Спроси goldratt: [система и её цель], [что предлагаем изменить],
> [мера результата]. Это узкое место?

Read-only: читает код, считает, предлагает проверки — ничего не меняет.
