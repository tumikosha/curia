# Агент `chesterton` на примере: «elon предложил снести пять вещей»

> **Что за агент.** `chesterton` — проверка причин перед сносом по забору
> Честертона: для каждого предлагаемого удаления найти автора, исходные
> причины и тех, кто на ограду успел опереться; снос с непонятой причиной
> блокируется до выяснения. Пара-антагонист `elon`: он предлагает удаления,
> chesterton отвечает на его графу «вернуть». Вход — предлагаемые удаления:
> отчёт elon, дифф, план. Полное определение:
> [`agents/chesterton.md`](../agents/chesterton.md).

Модельный прогон на проекте `http2md` — конвейере «URL → загрузка → разбор
HTML → markdown». Вход — отчёт `elon`, шаг 2: пять предлагаемых удалений.
Одна процедура, пять разных вердиктов.

## Ситуация

`elon` отработал по конвейеру и предложил снести: (1) `sleep(2)` перед
загрузкой каждой страницы, (2) проверку и подмену user-agent, (3) функцию
`parse_html_v2` — почти-дубль `parse_html`, (4) `helper.py`, (5) `handler.py`,
который единственный вызывает `helper.py`. По его квоте возвратов он ждёт
ответа на графу «вернуть».

Обычное ревью оценило бы, чист ли дифф удаления. `chesterton` спрашивает
другое: зачем каждая из этих оград стояла — и знаем ли мы это.

## Отчёт (сокращённо)

```
ВХОД
  удаления — отчёт elon, 5 оград; кластер: helper.py + handler.py
             (handler — единственный вызывающий helper)
  радиус   — репозиторий
  повторный вход — нет

ОГРАДА 1: sleep(2) перед загрузкой
  намеренность — ограда: добавлена отдельным коммитом b3f21a «fix»
  автор        — не найден: blame ведёт на подрядчика, ушедшего в 2024;
                 PR без описания; тикета нет; в доках не упомянута
  причины      — «гипотеза»: защита от rate-limit какого-то источника;
                 где искал: blame, PR, issues, docs/, README
  живость      — неизвестна: причина не установлена
  прислонились — не найдено (grep по репозиторию: вызовов и ссылок нет)
  обратимость  — доказана: одна строка, откат — revert одного коммита
  вердикт      — СТОП: программа — прогнать пакет из 50 URL без sleep
                 в песочнице против топ-5 источников из логов;
                 429/бан хотя бы от одного → «не снимать» с найденной
                 причиной; чисто → правило исчерпания: обратимость
                 доказана → «снимать со стражей»

ОГРАДА 2: проверка user-agent
  намеренность — ограда: тест test_user_agent_override существует
  автор        — найден: коммит e91c04, автор в команде
  причины      — установлена: тикет INC-17 — источник N банил дефолтный
                 UA питоновских библиотек (источник: сообщение коммита
                 → тикет)
  живость      — жива: источник N — в списке эталонного корпуса,
                 закреплённого в CI (fixtures/corpus.txt:12)
  вердикт      — НЕ СНИМАТЬ: причина INC-17 жива — источник N
                 по-прежнему обрабатывается

ОГРАДА 3: parse_html_v2 (почти-дубль)
  намеренность — не ограда: появилась в мерж-коммите без смысла,
                 теста нет, из соседей никто не вызывает
  прислонились — живых нет (grep: единственное упоминание — сам файл)
  вердикт      — СНИМАТЬ: НЕ ОГРАДА — мусор от кривого мержа

ОГРАДЫ 4–5: helper.py + handler.py (кластер, два прохода)
  проход 1, по собственным основаниям:
    handler — причина установлена (коммит: обход редиректов источника M),
              мертва: источник M выпилен из корпуса в 2025 (коммит 7d0a2e);
              гипотез нет; внешних прислонившихся нет
    helper  — причины установлены и мертвы (те же); единственный живой
              прислонившийся — handler, из этого же входа
  проход 2, увязка:
    handler — СНИМАТЬ; для elon «вернуть»: следить за долей ошибок
              редиректов в логах; откат — revert, дешев
    helper  — СНИМАТЬ ВМЕСТЕ С handler: после него или одним коммитом

СВОДКА
  снимать 3 (из них вместе 1, со стражей 0), не снимать 1
  (наследников и дефолтов 0), стоп 1 (эскалаций 0), не-ограда — учтена
  в «снимать», отказ 0

  графа elon «вернуть»: sleep(2) — решится программой стопа;
  user-agent — вернуть (причина жива); v2, helper, handler — не вернуть
  квота elon не считается, пока 1 стоп не разрешён

  самое дорогое утверждение отчёта — причины helper и handler исчерпаны
    коммитом 7d0a2e (выпил источника M)
  чем оно опровергается           — grep по логам прода за месяц:
    редиректы источника M ещё встречаются → причина жива, оба вердикта
    переворачиваются в «не снимать»
```

## Второй заход: программа стопа исполнена

Пакет из 50 URL прогнан без `sleep(2)` — чисто, ни одного 429. Повторный
вход: «программа исполнена, мир молчит».

```
ОГРАДА 1: sleep(2) — повторный вход
  вердикт — СНИМАТЬ СО СТРАЖЕЙ (правило исчерпания: молчание после
            исполненной программы терминально, обратимость доказана).
            Страж: доля 429/банов в логах загрузки; всплеск →
            снос был ошибкой, откат — revert b3f21a.

СВОДКА (обновлённая)
  стопов 0 → квота elon считается: возвратов 1 из 5 — 20%,
  квота 10% встречена
```

Стоп не стал вечным тормозом: программа была исполнима, молчание мира —
терминально, и ограда ушла — со стражем, а не с пожатием плеч.

## В чём польза

| | Обычное ревью | chesterton |
|---|---|---|
| Что видит | дифф удаления: чисто, тесты зелёные | пять историй: зачем каждая ограда стояла |
| «Никто не знает, зачем это» | аргумент за снос | аргумент против — и программа выяснения |
| Вердикт | «удаление одобрено» | 3 снимать, 1 не снимать (причина жива: INC-17), 1 стоп с программой |

Пара с `elon` сработала как задумано: он посмел предложить пять сносов, не
зная причин; chesterton раскопал причины и вернул одну ограду на место —
ровно та ошибка возврата, которую его квота считает дешёвой и обязательной.
