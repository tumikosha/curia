# Агент `chesterton` на примере: «список сноса на десять пунктов»

> **Что за агент.** `chesterton` — проверка причин перед сносом по забору
> Честертона: для каждого предлагаемого удаления найти автора, исходные
> причины и тех, кто на ограду успел опереться; снос с непонятой причиной
> блокируется до выяснения. Пара-антагонист `elon`: он предлагает удаления,
> `chesterton` отвечает на его графу «вернуть». Вход — предлагаемые
> удаления: отчёт `elon`, дифф, план. Полное определение:
> [`agents.ru/chesterton.md`](../agents.ru/chesterton.md).

Прогон вслепую на артефакте [`bench/corpus/ch1`](../bench/corpus/ch1/):
агент получил список сноса и репозиторий, больше ничего. Модель — Sonnet.

## Вход

Сервис выгрузки биллинга перед переездом на новую схему. Предложено
снести десять вещей: ретрай на 429, старую таблицу попыток,
закомментированный блок, нормализацию IBAN, проверку отрицательной
суммы, публичную ручку статуса, две функции CSV-пути, паузу в релизном
скрипте и колонку с последними цифрами карты.

В репозитории рядом — выдержка из истории коммитов, тикеты, changelog,
SLA платёжного шлюза, контракт API и состав команды. Все причины
восстанавливаются оттуда, если их искать.

Обычное ревью оценило бы, чист ли дифф удаления. `chesterton`
спрашивает другое: зачем каждая из этих оград стояла — и знаем ли мы
это. Десять оград, шесть разных вердиктов.

## Отчёт (сокращённо)

```
ВХОД
  удаления — deletions.md, оформлен по образцу отчёта elon, 10 оград;
             кластеры: пункты 7 (_fmt_row) и 8 (write_csv) связаны —
             write_csv единственный вызывающий _fmt_row, судятся вместе
  радиус   — репозиторий (task.md)
  повторный вход — нет
```

**Ограда 1 — ретрай на 429.** Автор найден и жив, причина установлена:
шлюз троттлит на 50 rps, PSP-114.

```
живость      — жива: docs/gateway-sla.md — договор продлён 2026-07-01
                без изменений, ретраи обязательны по п.4.2; замер за
                август 2026 — пик 61 rps, 429 приходили 14 раз за месяц
прислонились — живой, извне входа: billing/charge.py:3,9 — действующий
                путь списаний
вердикт      — не снимать — причина жива и живой потребитель
```

Обоснование сноса во входе — «шлюз и так стабилен» — единственное во
всём списке утверждение о внешнем мире без источника. Оно опровергнуто
файлом, лежащим в том же радиусе.

**Ограда 2 — таблица `export_attempts_v1`.** Причина установлена и
мертва: BIL-201 требовал снести через неделю после переключения,
переключение завершено 2026-03-09.

```
обратимость  — пересоздание таблицы миграцией — пустая оболочка без
                исторических данных (бэкап строк нигде не упомянут)
                → отката нет
вердикт      — снимать — для elon «вернуть»: заметить ошибку по
                обращениям вида «relation export_attempts_v1 does not
                exist»; отката нет — страж: мониторить логи БД на
                обращения к v1 в течение ~30 дней, сигнал = хотя бы
                одно обращение
```

Здесь видно правило, которого нет у обычного ревью: механизм,
восстанавливающий пустую оболочку, откатом не считается — и вердикт
«снимать» обязан нести стража.

**Ограда 3 — закомментированный блок.** Не ограда: история прямо
говорит, что блок попал в файл дважды при разрешении конфликта мержа.
Шаг «кто прислонился» пройден всё равно — на мусор тоже опираются.

```
вердикт      — снимать: не ограда
```

**Ограда 4 — `normalize_iban`.** Исходная причина мертва: функцию
завели ради Nordbank, тот прекратил приём выплат 2026-02-14.

```
прислонились — живой, извне входа: reports/monthly.py:3,10 — вызывается
                для всех выплат месяца, cron 1-го числа; в список сноса
                не входит, от Nordbank не зависит
вердикт      — не снимать — живой прислонившийся; исходная причина
                мертва, но функцию нагрузил новый, непредвиденный при
                постройке потребитель
```

Ровно тот случай, ради которого существует пятый шаг. Мёртвая исходная
причина сноса не разрешает: ограда несёт новый груз.

**Ограда 5 — проверка отрицательной суммы.** Автора нет: коммит «fix»
без тикета, единственный подозреваемый уволился, владельца у файла нет.
Поиск по трекеру дал явный ноль.

```
причины      — не установлены. Единственная возможная формулировка
                источника не имеет → гипотеза, не снимается
вердикт      — стоп — программа: (1) поднять полную git-историю по
                строке за пределами выдержки — найдёт коммит и тикет;
                (2) найти вызывающий код за пределами среза. При
                повторном входе с молчанием мира и доказанной дешёвой
                обратимости — «снимать со стражей»
```

**Ограда 6 — публичная ручка статуса.** Контракт прямо признаёт, что
зачем её заводили и кто просил — не записано.

```
прислонились — «неизвестно»: публичная поверхность, grep по
                репозиторию её не закрывает; список интеграторов не
                ведётся, телеметрия вне доступа
вердикт      — стоп — программа: (1) телеметрия по эндпоинту за 90
                дней: нулевой трафик снимает вопрос, ненулевой → «не
                снимать»; (2) спросить владельца домена экспорта и
                команду, публиковавшую контракт
```

Пустой grep здесь ничего не доказывает: ограда видна наружу радиуса.

**Ограды 7 и 8 — `_fmt_row` и `write_csv`.** Причина CSV-пути мертва:
его читал только Nordbank, вызовов из планировщика нет с 2026-05-04.
Единственный живой потребитель `_fmt_row` — это `write_csv`, который
сносят тем же списком.

```
вердикт (7)  — снимать вместе с write_csv — порядок: одним коммитом
                убрать оба, чтобы не оставить сломанный импорт в
                промежуточном состоянии
вердикт (8)  — снимать — откат: git revert, дёшево и полно
```

Прислонившийся из того же входа делает вердикт условным, а не
запретительным.

**Ограда 9 — пауза в релизном скрипте. Ловушка.** Над ней стоит
комментарий «не трогать, так исторически сложилось».

```
намеренность — ограда: несмотря на комментарий (сам по себе — образец
                поклонения оградой, недостаточен как причина), реальная
                причина восстанавливается независимо
причины      — «healthcheck race — после rollout под ещё не в endpoints,
                curl ловит 503» — коммит 1f88ac3
живость      — не проверена: нет доказательства смерти и нет прямого
                доказательства продолжающейся жизни. Отсутствие
                доказательства смерти — не жизнь, а третье состояние
вердикт      — стоп — программа: спросить p.novak, найденного живого
                автора; дополнительно прогнать релиз в песочнице без
                паузы. «Гонка ещё есть» → не снимать; «устранена» и
                чистая песочница → снимать со стражей
```

Комментарий как защита не сработал и не должен был. Настоящая причина
нашлась в коммите — и именно она, а не надпись, отправила ограду в стоп.

**Ограда 10 — колонка с цифрами карты.** Снос уже исполнен: миграция
применена в прод, бэкап не снимался.

```
вердикт      — ОТКАЗ — снос исполнен и необратим → premortem-reviewer
                и разбор инцидента, не археология задним числом
```

```
СВОДКА
  снимать 3 (из них вместе 1, со стражей 0), не снимать 2,
  стоп 3, не-ограда 1, отказ 1

  K = 3 > 0 → квота elon не считается, пока 3 стопа не разрешены

  самое дорогое утверждение отчёта — пункт 1: «шлюз и так стабилен»
    как обоснование сноса ретрая
  чем оно опровергается — docs/gateway-sla.md: замер за август 2026,
    пик 61 rps выше договорного лимита 50 и 14 срабатываний 429;
    ретраи предписаны п.4.2 действующего договора
```

— `chesterton`

## Второй заход: программа стопа исполнена

Стоп не бывает бессрочным. Допустим, по ограде 9 спросили автора, и он
ответил «не помню». Ответ «не помню» читается как молчание, программа
исполнена — дальше работает правило исчерпания, и оно смотрит в графу
обратимости:

- обратимость доказана (правка одной строки, `git revert`) →
  **снимать со стражей**: страж — доля неуспешных первых
  healthcheck-попыток в пайплайне после снятия;
- если бы обратимость доказана не была → **стоп-эскалация** к
  владельцу радиуса с вопросом, на который отвечает только он.

Повторять исполненную программу или выдавать новый стоп той же
программы запрещено — это и есть бессрочный стоп. Молчание адресата
эскалации тоже терминально: оно фиксируется как «не снимать — дефолт
владельца радиуса».

## В чём польза

| | Обычное ревью | chesterton |
|---|---|---|
| Что смотрит | чист ли дифф удаления | зачем стояло сносимое и знаем ли мы это |
| «Никто не знает, зачем это» | аргумент за удаление | аргумент против: незнание причины — незнание последствий |
| «Не трогай, так исторически сложилось» | принимается как защита | не причина; причина ищется в истории |
| Мёртвая исходная причина | достаточно для сноса | недостаточно: ограда могла набрать новый груз |
| Пустой grep | доказательство | не доказательство для публичной поверхности |
| «Легко вернём» | принимается на слово | механизм или «отката нет» + страж |
| Итог | «LGTM» / «страшно, не трогай» | шесть разных вердиктов, у каждого стопа — программа с исходом |

Из десяти предложенных удалений безусловно снимаются три, два
блокируются живой причиной и живым потребителем, три уходят в
выяснение, одно оказывается мусором, одно — уже состоявшимся
необратимым сносом. Ни одного «страшно, оставим»: каждый отказ снести
назван поимённо и с источником.
