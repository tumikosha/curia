# Агент `descartes` на примере: «дизайн кэша, где всё очевидно»

> **Что за агент.** `descartes` — проверка рассуждения по четырём правилам
> метода: очевидность (несущие предпосылки со статусом — очевидна, доказана,
> на веру, без статуса, противоречит входу), деление, порядок от простого к
> сложному, полнота перечней. Ловит несущую предпосылку без статуса — здание
> стоит на непроверенном — и дырявый перечень: «все случаи» без
> доказательства полноты. Вход — артефакт, желательно с рассуждением. Полное
> определение: [`agents/descartes.md`](../agents/descartes.md).

Модельный прогон на проекте `http2md` — конвейере «URL → markdown».
Один дизайн, два прогона.

## Вход

RFC «Дисковый кэш скачанных страниц» плюс прототип. Обычное ревью
похвалит: аккуратно, с примерами, код чистый.

## Прогон 1

```
ПРАВИЛО 1. ПРЕДПОСЫЛКИ (только несущие)
  «SQLite выдержит наши параллельные записи»
    — несёт: если ложно — рушится весь выбор хранилища
    — статус: БЕЗ СТАТУСА — в RFC вшито как факт (rfc.md:14), ни
      замера, ни пометки; шаг очевидности существует: раздел «When to
      use» в доке SQLite + число воркеров из config.py:8
  «Диск локальный, fsync дёшев»
    — несёт: если ложно — рушится оценка латентности
    — статус: на веру (помечена: rfc.md:31 «assume local disk») — успех
  «retries=3, потому worst-case 15 секунд»
    — статус: ПРОТИВОРЕЧИТ ВХОДУ — в коде retries = 5 (fetch.py:22);
      найдено при цитировании веток для правила 4

ПРАВИЛО 2. ДЕЛЕНИЕ — части проверяемы порознь: запись / чтение /
  инвалидация. Монолита нет.

ПРАВИЛО 3. ПОРЯДОК — сложное без базы: в RFC обобщённый интерфейс
  «Backend» под «будущие движки» — а разобранного простого случая
  (один движок, один воркер) в рассуждении нет. На дизайне базой
  служит разобранный случай, не работающий код, — но нет и его.

ПРАВИЛО 4. ПЕРЕЧНИ (только несущие)
  типы ответа сервера: 200, 304, 404, «и прочие»
    — несёт: если дыра — непойманный тип молча портит кэш
    — статус: ДЫРЯВ — «прочие» уходят в default: pass (cache.py:47);
      полнота не доказана, остаток проглочен

ВЕРДИКТ — стоит на непроверенном: «SQLite выдержит параллельные
  записи» — несущая, без статуса. Предъявить: шаг очевидности (док +
  число воркеров), источник (замер) или пометку «на веру» — в RFC,
  не в переписку.
  Остальные находки — в секциях: противоречие retries (согласовать),
  дырявый перечень (дешевле всего — пометить с компенсацией: ошибка
  наверх вместо pass), обобщение без базы (разобрать случай одного
  движка).

  самое дорогое утверждение отчёта — «SQLite выдержит» несёт весь
    выбор хранилища
  чем оно опровергается — замер: N воркеров из config.py пишут
    минуту в одну базу; SQLITE_BUSY чаще нуля — предпосылка мертва
```

Заметь: агент не сказал «SQLite не выдержит» — охота на ложность не
его работа. Он сказал: это вера, она несущая, и она не помечена.

## Прогон 2: повторный вход

Автор: замер прогнан (доказана: benchmark.md), retries в RFC исправлен
на 5, «прочие» типы падают ошибкой наверх с пометкой «полнота не
доказана», случай одного движка разобран в RFC перед интерфейсом.

```
ВЕРДИКТ — рассуждение стоит.
  Помеченная вера: «диск локальный» (rfc.md:31), «полнота типов не
  доказана» (cache.py:47) — видна и управляема; при высокой цене
  ошибки — охотничий список для adversarial.

  самое дорогое утверждение отчёта — замер benchmark.md репрезентативен
    боевой нагрузке
  чем оно опровергается — сравнить профиль записи в замере с недельным
    логом прода
```

## В чём польза

| | Обычное ревью | descartes |
|---|---|---|
| Что видит | аккуратный RFC, чистый код | на чём RFC стоит: две веры, одна без пометки |
| «Все случаи обработаны» | верит | «прочие» → default: pass — дыра, не обработка |
| Вердикт | «выглядит хорошо» | стоит на непроверенном: вот предпосылка, вот шаг |

Дизайн не стал хуже от того, что его вера помечена, — он стал честным:
здание знает, на чём стоит, и охотнику есть куда идти.
