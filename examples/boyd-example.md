# Агент `boyd` на примере: «мы деплоим каждый день — у нас всё быстро»

> **Что за агент.** `boyd` — петля OODA: наблюдение → ориентация →
> решение → действие. Проверяет, замкнута ли петля (каждое действие
> возвращается наблюдением результата, и канал кто-то читает) и короче ли
> полный оборот темпа среды. Выигрывает не лучшее решение, а более
> короткий цикл. Ловит полировку решения при цикле длиннее темпа,
> разорванную петлю и замёрзшую ориентацию. Вход — петля или материал для
> её восстановления, желательно темп среды. Полное определение:
> [`agents/boyd.md`](../agents/boyd.md).

Модельный прогон на проекте `http2md` — конвейере «URL → markdown».
Одна петля, три прогона.

## Ситуация

Команда гордится: «деплоим парсер каждый день». Петля — качество
конвертации: пользователи жалуются на битые страницы, команда правит
парсер, катит, идёт дальше.

## Прогон 1

```
ВХОД
  петля — восстановлена из: issues, git log, grafana/
  темп среды — восстановлен: changelog топ-20 доменов корпуса —
    вёрстка источников меняется каждые [2–6] недель (внешний источник)
  классы действий — деплой парсера, правка эталонного корпуса

ПЕТЛЯ
  наблюдение — жалобы в issues (канал есть); дашборд доли битых
    страниц СУЩЕСТВУЕТ (grafana/parse-rate.json)
  ориентация — РАЗРЫВ: следов чтения дашборда нет — ни разбора в
    синке, ни правки картины, ни реакции на алерт за 4 месяца
    (git log docs/, протоколы синков); канал без читателя — архив
  решение — лид, за день (заявлено — подтвердить)
  действие — деплой ежедневно (git log)
  оборот — полный, до возврата наблюдения: жалоба → фикс → деплой →
    ...первая реакция на метрику — НЕ ЗАМЫКАЕТСЯ

ВЕРДИКТ — петля разорвана — замкнуть: ориентация не читает
  собственный дашборд; ежедневный деплой не делает петлю быстрой —
  действие без усвоенного результата это половина оборота.
  Программа: пятничный разбор parse-rate по топ-доменам, 15 минут;
  алерт на падение доли ниже 95%.

  самое дорогое утверждение отчёта — дашборд никто не читает
  чем оно опровергается — один след чтения за 4 месяца: правка
    картины или реакция на алерт с датой
```

«Каждый день деплоим» оказалось скоростью действия, не петли: оборот
измеряется до возврата наблюдения, а он не наступал.

## Прогон 2: канал замкнули — теперь темп

Пятничный разбор введён. Повторный вход через месяц.

```
ПЕТЛЯ
  оборот — полный: жалоба/метрика → разбор (до 5 дней ожидания
    пятницы) → фикс → деплой → метрика в следующий разбор =
    [7–12] дней (даты четырёх оборотов)

ТЕМП СРЕДЫ
  вёрстка источников — [2–6] недель (changelog, внешний)

СРАВНЕНИЕ — оборот [7–12] дней короче темпа [14–42] дней, но вилки
  близки на нижней границе темпа

ВЕРДИКТ — держать темп — запас ×1,2–6; узкая стадия на будущее:
  ожидание пятницы (до 5 из 7–12 дней — ориентация по расписанию,
  а не по сигналу). Класс «деплой парсера» обратим: канареечный
  прогон на 100 страницах + revert — механизм назван, вердикт
  безусловен.

  самое дорогое утверждение отчёта — темп источников [2–6] недель
    репрезентативен: changelog топ-20 покрывает корпус
  чем оно опровергается — дрейф хвоста: доля битых страниц вне
    топ-20 за тот же месяц
```

## Прогон 3: соседний вход — не наш

«Ускорим правку корпуса: наймём второго редактора» — изменение с
вопросом «туда ли направлена работа» → перенаправление `goldratt`:
узкая стадия этой петли — ожидание пятницы, а не руки редактора,
и его пять шагов проверят это как ограничение.

## В чём польза

| | Самооценка команды | boyd |
|---|---|---|
| «Мы быстрые» | деплой каждый день | оборот не замыкался вовсе: действие без усвоения |
| Метрики | «у нас есть дашборд» | канал без читателя — архив |
| Скорость | полировать решения | сократить ожидание пятницы: ориентация по сигналу |

Скорость петли — не скорость действия, а скорость полного оборота: до
момента, когда результат вернулся и изменил картину. Всё остальное —
бег на месте с частым шагом.
