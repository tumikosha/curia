# Агент `franklin` на примере: «включать ли телеметрию по умолчанию»

> **Что за агент.** `franklin` — моральная алгебра из письма Пристли 1772:
> два столбца доводов и вычёркивание равновесного вместо подсчёта; остаток и
> есть решение. Два вида суждений веса — эквивалентность и доминирование, —
> оба аудируемы и подтверждаются решающим; веса агент не выдумывает. Ловит
> счёт вместо веса — толпу лёгких доводов против одного тяжёлого. Вход —
> бинарное решение, доводы, материал. Полное определение:
> [`agents/franklin.md`](../agents/franklin.md).

Модельный прогон на проекте `http2md` — конвейере «URL → markdown». Одно
решение, два прохода и одно перенаправление.

## Ситуация

Команда спорит: включать ли в CLI телеметрию по умолчанию — отправку
обрабатываемых URL для приоритизации эталонного корпуса. Голосовали:
четыре довода «за», два «против» — «большинством решили включать».
`franklin` существует ровно против этого способа решать.

## Проход 1: столбцы, суждения, вопрос

```
ВХОД
  решение  — телеметрия включена по умолчанию: да / нет
  решающий — владелец проекта
  доводы   — от вызывающего: 4 за, 2 против; добрано агентом: 1
  повторный вход — нет

СТОЛБЦЫ
  ЗА
    З1 приоритизация корпуса по реальным URL — строка входа
    З2 быстрее находим падающие источники — строка входа
    З3 метрика для поста о проекте — строка входа
    З4 «у всех есть телеметрия» — строка входа
  ПРОТИВ
    П1 пользователи шлют нам свои URL — приватность — строка входа
    П2 GDPR-обработка адресов — строка входа — пометка:
       «истинность — suntzu» (потянем ли комплаенс — не мой вопрос)
    П3 в issues уже жалоба на «звонки домой» у соседнего тула,
       пользователь обещает уйти — добран агентом: issues/112
  склейки — З1 и З2 слиты: один мотив «знать реальные входы» (З1+З2)
  добор   — где искал: README, issues, docs/, переписка в PR; найдено П3

СУЖДЕНИЯ ВЕСА
  1. [экв 1:1] З3 (метрика для поста) ~ П2 (GDPR-хлопоты)
     обоснование: оба — периферийные удобства/хлопоты, не судьба продукта
     решающее: да — статус: предложено
  2. [экв 1:1] З4 («у всех есть») ~ вычеркнуть не с чем — НЕ ПРЕДЛОЖЕНО;
     довод остаётся в остатке с пометкой «нужность — elon»
  доминирование П1+П3 над остатком ЗА — основания в материале нет:
  вопрос вынесен в программу

ОСТАТОК
  ЗА: З1+З2 (знать реальные входы), З4    ПРОТИВ: П1, П3

ВЕРДИКТ — равновесие — алгебра не решает («взвешено и сократилось»
  частично: остаток по обе стороны).
  Программа — прямой вопрос решающему о доминировании: перевешивают ли
  приватность и риск ухода пользователей (П1+П3) пользу знания реальных
  входов (З1+З2, З4)? Ответ «да» создаёт доминирование и решает ПРОТИВ;
  ответ «нет» возвращает спор — и тогда самая дешёвая проверка веса П3:
  спросить автора issues/112, уйдёт ли он при opt-out.

  самое дорогое утверждение отчёта — эквивалентность №1 (пост ~ GDPR)
  чем оно опровергается           — решающий отклоняет пару: GDPR для
    него не «хлопоты», а красная линия — П2 возвращается в остаток
```

Заметь: агент не сказал «4 против 2 — включать». Он не сказал и «privacy
важнее» от себя — веса принадлежат решающему, и тяжёлый вопрос задан ему
прямо.

## Проход 2: повторный вход

Решающий отвечает: пару №1 подтверждаю; на вопрос программы — «да,
доверие пользователей перевешивает всю пользу корпуса, это писал и в
README проекта: privacy-first».

```
СУЖДЕНИЯ ВЕСА (пересчёт)
  1. [экв 1:1] З3 ~ П2 — подтверждено
  2. [доминирование] П1+П3 над З1+З2, З4 — основание: ответ решающего +
     README.md:14 «privacy-first» — подтверждено

ОСТАТОК
  ЗА: пусто    ПРОТИВ: П1, П3 (доминируют)

ВЕРДИКТ — решение: НЕ включать по умолчанию — безусловно:
  все суждения остатка подтверждены.
```

## Перенаправление: не всякое «делать/не делать» — franklin

Через неделю приносят другое решение: «переписать sync-ядро на async до
демо — да/нет». Доводы: «быстрее» («истинность — suntzu»), «не успеем»
(«истинность — suntzu»), «упадёт демо» («истинность — suntzu»).

```
ВЕРДИКТ — перенаправление к suntzu: остаток целиком на доводах
  «истинность — suntzu», спора о желаниях нет. Это расчёт похода —
  силы, сроки, обстановка, — а не взвешивание мотивов. Отчёт не выдаётся.
```

Оба хотят одного (успешное демо) — спорят о фактах мира. franklin нужен
там, где факты известны, а спор — о том, чего мы хотим.

## В чём польза

| | Голосование / обычное обсуждение | franklin |
|---|---|---|
| Как решает | большинством пунктов | вычёркиванием равновесного; тяжёлое спрашивает прямо |
| Кто взвешивает | тот, кто громче | решающий — по выложенной картине |
| Аудит | «мы так решили» | каждое суждение веса: обоснование, статус, что меняет отклонение |

Четыре довода против двух проиграли — потому что доводы взвешивают, а не
считают.
