# Агент `bezos` на примере: «три недели обсуждаем формат вывода»

> **Что за агент.** `bezos` — классификация решения до выбора скорости:
> дверь двусторонняя (обратимая) или односторонняя, и соразмерен ли процесс
> типу двери. Обратимость доказывается механизмом отката, а не словом
> «откатим»; фирменный ход — сузить необратимое дизайном: флаг, canary,
> бэкап. Ловит месячное обсуждение откатываемого за час и необратимое на
> бегу. Вход — решение и процесс его принятия. Полное определение:
> [`agents/bezos.md`](../agents/bezos.md).

Модельный прогон на проекте `http2md` — конвейере «URL → markdown».
Четыре решения, четыре двери, четыре разных вердикта.

## Решение 1: смена формата markdown-вывода — три недели обсуждений

Команда третью неделю спорит о новом формате заголовков в выводе; за
флагом `--format-v2` формат уже реализован. В треде 4 человека и 40
сообщений.

```
ТЕСТ ДВЕРИ
  механизм отката — выключение флага --format-v2 (cli.py:88)
  цена отката     — одно штатное действие; улика — сам механизм
  право отката    — у нас
  осадок          — не найден: искал в issues, README, обсуждении PR

СОПОСТАВЛЕНИЕ
  цена процесса — 4 человека × 3 недели треда (PR #61, 40 сообщений)
  против цены отката — выключение флага; обсуждение дороже отката
  на порядки

ВЕРДИКТ — дверь двусторонняя — решать быстро: владельцем CLI,
  единолично. Дефект первый: обсуждение (3 недели × 4 человека)
  дороже отката (один флаг). Скорость — тоже актив, её потеря
  необратима.

  самое дорогое утверждение — осадка нет
  чем опровергается — жалоба пользователя на смену формата в issues
    после включения: появится — флаг выключается, спор возобновляется
    уже с уликой
```

## Решение 2: «перепишем кэш на SQLite, потом откатим если что»

```
ТЕСТ ДВЕРИ
  механизм отката — не назван: «откатим» в треде (PR #64) — не механизм
  цена отката     — неизвестно
  ...

ВЕРДИКТ — ложная двусторонность — стоп: обратимость заявлена, тест
  провален (механизм не назван). До предъявления дверь односторонняя,
  процесс — полный. Программа — самое дешёвое предъявление: назвать
  механизм (файловый кэш регенерируем? бэкап?), затем право, затем
  прогон отката на стенде.
```

Повторный вход: «кэш регенерируется с нуля за минуты, откат — удалить
файл SQLite и вернуть флаг» → переклассификация → **двусторонняя —
решать быстро**. Слово «откатим» стало механизмом — и только тогда
купило скорость.

## Решение 3: «включить новый парсер всем пользователям»

Парсер переписан; предлагают включить всем сразу — «обсудили на
стендапе».

```
ТЕСТ ДВЕРИ
  механизм отката — revert есть, но осадок: страницы, сконвертированные
  с ошибками за время инцидента, уйдут пользователям — не вернуть

СУЖЕНИЕ
  canary: флаг + 5% пользователей на неделю; цена — день работы;
  ядро (полный переход) остаётся, но решается после canary с уликами

ВЕРДИКТ — дверь сужается — вот ход: canary 5% (день работы) плюс
  полный процесс ядра дешевле полного процесса целого. Оболочку
  (canary) решать быстро; ядро (переход всех) — после недели улик.
```

## Решение 4: «опубликовать пакет на PyPI, решили в чате за вечер»

```
ТЕСТ ДВЕРИ
  механизм отката — публикацию не отозвать: имя занято навсегда,
  право отката — у PyPI, не у нас; осадок — имя, версия, зависимые

ВЕРДИКТ — дверь односторонняя — полный процесс. Необратимо: имя
  пакета, схема версий, появившиеся зависимые. Дефект второй: «решили
  в чате за вечер» — лёгкий процесс на односторонней двери. Чего не
  хватает: проверка имени на коллизии, схема версионирования, прогон
  на test.pypi.org (это и сужение: репетиция без ядра).
```

## В чём польза

| | Обычный процесс | bezos |
|---|---|---|
| Как выбирает скорость | одна скорость на всё: у кого-то всё через RFC, у кого-то всё в чате | сначала классифицирует дверь, потом скорость |
| «Потом откатим» | принимается на слово | механизм или стоп |
| Вердикт | «обсудим ещё» / «погнали» | флаг — решай один сегодня; PyPI — зажги весь свет |

Три недели на обратимый флаг и один вечер на вечное имя пакета — одна
и та же команда совершает оба дефекта сразу. Дверь классифицируют до
выбора скорости, а не после.
