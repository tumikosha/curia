# Curia — команда ревью каталога

**Curia** (лат. «судебный двор») — коллегия над делом-артефактом:
двадцать один агент — девятнадцать судей, каждый с одним вопросом,
свод (`review-arbiter`) и триаж (`larrey`).
Этот документ — протокол их совместной работы: кто выбирает состав,
как ревьюеры изолированы, кто сводит и где команда останавливается.
Исполняемая версия протокола — агент [`larrey`](agents.ru/larrey.md)
(триаж); человеку достаточно этой страницы.

## Роли

- **`larrey`** — триаж: по входу назначает состав (≤4), порядок,
  вход каждому. Не судит и не запускает — назначает; исполняет
  вызывающий.
- **Ревьюеры** — девятнадцать судей, каждый со своим вопросом (см.
  таблицу ниже и `agents.ru/*.md`).
- **`review-arbiter`** — свод: при двух и более отчётах отсеивает
  недоказанное, разрешает конфликты, выносит единственный голос
  команды.
- **Вызывающий** — главный агент сессии или человек: запускает
  назначенных, передаёт отчёты в свод.

## Словарик

- **Фаза** — где живёт вход: работа ещё не начата (A), идёт (B) или
  предъявлена готовой (C).
- **База (стартовый состав)** — судьи, которых зовут по умолчанию,
  просто потому что вход в этой фазе, — когда ничего специфичного в
  артефакте нет.
- **Триггер (примета входа)** — конкретный признак в артефакте
  (числа, удаления, инцидент…), который добавляет профильного судью
  или ставит его на место нерелевантного базового.
- **Носитель вопроса** — судья, отвечающий за вопрос вызывающего:
  по совпадению смысла, а при незаданном вопросе — назначенный
  базовый судья фазы; из состава не вырезается никогда.
- **Такт** — один заход: назначенные работают параллельно и сдают
  отчёты; тактов максимум два.
- **Ёмкостный отрез** — вырезание судьи только из-за лимита ≤4, по
  фиксированному порядку; это не оценка «он не нужен», и вызывающий
  волен поднять лимит.
- **Свод** — превращение нескольких отчётов в один вердикт
  (`review-arbiter`); **«непокрыто»** — честный список того, что
  команда не успела рассмотреть за два такта.
- **Раунд** — полный цикл «триаж → такты → свод»; после правок
  артефакта возможен второй; дальше решает владелец.

## Фазы и составы

Как собирается состав, по шагам:

1. `larrey` определяет **фазу** — по вопросу вызывающего («стоит
   ли?» — значит, до старта); вопрос не задан — по состоянию работы.
2. Берётся **стартовый состав фазы** из первой таблицы — дефолт на
   случай, когда в артефакте нет ничего специфичного.
3. Артефакт просматривается на **приметы** из второй таблицы: есть
   числовое обещание — добавляется `fermi`; есть удаления —
   `chesterton`; вход — постмортем, и сверять его не с чем —
   `contract-reviewer` выбывает, его место занимают `ohno` и
   `darwin`.
4. Стало больше четырёх — режем: сначала стартовый состав (по
   фиксированному порядку), затем приметных снизу второй таблицы;
   носитель вопроса не режется никогда. Каждый вырезанный назван
   поимённо с причиной.

| фаза | вопрос | стартовый состав (база) |
|---|---|---|
| **A** до старта | «делать ли / выиграем ли / не умрём ли» | `hamming` + `suntzu` + `munger` |
| **B** в работе | «как разобрать / туда ли копаем» | `descartes` + `polya` |
| **C** готовое | «сделано — проверь» | `contract-reviewer` + `adversarial` |

Приметы входа (триггеры). Строки отранжированы по профильности:
нижние — самые широкие, при ёмкостном отрезе режутся первыми.

| триггер во входе | агент | его вопрос |
|---|---|---|
| числовое обещание, лимит | `fermi` | сходится ли арифметика |
| предстоящий необратимый шаг, скорость решения | `bezos` | какая дверь и соразмерен ли процесс |
| инцидент, RCA, фикс | `ohno` | докопан ли корень, стоит ли на месте |
| вывод + материал наблюдений | `darwin` | где записано противоречащее |
| удаления | `chesterton` | понята ли причина ограды |
| оптимизация с мерой | `goldratt` | в ограничение ли работа |
| компромисс, боль без решения | `altshuller` | разрешено ли противоречие |
| повторяющийся цикл, темп | `boyd` | замкнута ли петля, короче ли темпа |
| бинарная развилка с доводами | `franklin` | что останется после вычёркивания |
| длинное или неоднозначное ТЗ у готового | `reverse-spec-reviewer` | какое ТЗ решает артефакт |
| готовое перед необратимым применением: миграция данных, прод-конфиг, деплой без отката | `premortem-reviewer` | как это провалилось |
| просьба упростить или сократить; требование без названного источника | `elon` | оспорить, удалить, упростить |

Одиночный вход: вопрос вызывающего совпадает с юрисдикцией одного
агента **и других детектируемых триггеров во входе нет** — состав
из одного; свод по общему правилу (передача такта 2 добавила второй
отчёт → арбитр обязателен). Триггеры бьют формулировку вопроса:
удобная формулировка не подавляет детектируемое в артефакте;
юрисдикционный вопрос к небазовому агенту с триггерами строит
состав от носителя вопроса плюс триггерные, база фазы не
добирается; вопрос, совпадающий с юрисдикцией базового, — фазовое
ревью: база добирается, носитель — совпавший базовый.
Составной вопрос (несколько фаз, либо фазовый плюс
юрисдикционный) — два входа, каждому свой состав, порядок по
фазам: A раньше B, B раньше C; общий лимит двух раундов.

## Протокол

1. **Соразмерность.** Первый такт ≤4. Причины отреза двух категорий:
   «вопрос не задет» — из строк входа («franklin не зван: развилки
   нет»); ёмкостный отрез — «лимит + позиция в порядке отреза»,
   рационализация поверх запрещена. Порядок отреза един: сначала
   база — A: suntzu → hamming → munger последним; B — polya →
   descartes; C — adversarial → contract-reviewer; затем
   триггерные — в обратном порядке строк таблицы триггеров (нижние
   режутся первыми).
   **Носитель вопроса назначается до всяких отрезов и не
   отрезается** — место вне конкурса. Назначение по смыслу: вопрос
   вызывающего совпадает с юрисдикцией агента — он и носитель.
   Совпадение с юрисдикцией **базового** агента фазы не делает
   вопрос юрисдикционным: база добирается как обычно, носитель —
   совпавший базовый («выиграем ли?» → носитель `suntzu`, база A
   при нём); состав «от носителя без базы» — только для небазовых
   агентов. При незаданном вопросе носитель — последний базовый в
   порядке отреза фазы (A — `munger`, B — `descartes`,
   C — `contract-reviewer`). База режется по порядку, но до одного —
   носителя; дальнейшие ёмкостные отрезы переходят на триггерных.
   Носитель выбыл через замещение — носителем становится последний
   оставшийся базовый; база опустела целиком — носитель, первый из
   заместивших, и обязательная строка назначения и свода: «вопрос
   вызывающего судится замещённым составом — кем». Базовый
   с незадетым вопросом отрезается и без замены — состав меньше
   базового легален. Молча пропавший — дыра, отрезанный с
   причиной — решение.
2. **Пауза при ёмкостном отрезе.** Назначение без ёмкостных отрезов
   исполняется сразу. Был ёмкостный отрез — вызывающий показывает
   назначение владельцу до исполнения: состав, отрезанные с
   причинами; владелец поднимает лимит или подтверждает. При любом
   исходе — подтвердил, промолчал, режим автономный — исполняется
   назначенный состав, а отрезанные уходят в «непокрыто» свода:
   вердикт честно называет, чьи вопросы не судились. Ёмкостно отрезанный, вернувшийся
   передачей такта 2, из «непокрыто» выходит: его вопрос отсужен —
   свод это фиксирует строкой.
3. **Изоляция.** Ревьюеры такта работают параллельно и не видят
   чужих отчётов до сдачи своего — прочитавший чужой чеклист
   становится его копией. Вход каждому — исходный артефакт целиком
   плюс указание, что нужно его вопросу; без пересказов.
4. **Такт 2 — передачи.** Строки перенаправления из отчётов
   («доказательство у fermi», «clearance bezos», «отброшенные —
   premortem») исполняются одним дополнительным тактом, ≤2 агентов.
   Присутствие адресата в такте 1 передачу не закрывает — он
   работал изолированно и находки не видел; повторный вызов
   участника такта 1 с находкой — легальный такт 2.
5. **Остановка после второго такта.** Остаток передач свод помечает
   «непокрыто — отдельным вызовом по решению владельца»: ревью
   сходится за два такта или честно называет остаток.
6. **Свод.** ≥2 отчётов → `review-arbiter` обязателен; его вердикт —
   единственный голос команды. Триаж не судит, судьи не сводят,
   арбитр не назначает.
7. **Повторный вход.** После правок — триаж по дельте: званы только
   агенты, чьи вопросы задеты правками, плюс свод; дельта переписала
   артефакт целиком — полный состав. Цикл ограничен двумя командными
   раундами, дальше эскалация владельцу. **Счётчик раундов ведёт
   вызывающий**: номер передаётся на вход и триажу («раунд N из 2»
   в roster), и арбитру; одиночное ревью без свода — тоже раунд и
   тоже инкремент. Повторный вход счётчик не сбрасывает.

## Сквозной пример

Вход: «план — мигрировать биллинг на новый платёжный шлюз до конца
квартала; все транзакции через новый, старый выключен. Стоит ли
начинать?»

1. `larrey`: фаза A (вопрос «стоит ли»); база `hamming` + `suntzu` +
   `munger`; триггеры: дедлайн-число → `fermi`, предстоящее
   выключение старого — необратимый шаг → `bezos`. Пять при лимите
   четыре: носитель назначен до отрезов — по смыслу вопроса
   «стоит ли» это `hamming`, он вне конкурса; по фиксированному
   порядку отреза базы A уходит `suntzu` — ёмкостный отрез: лимит 4,
   первый в порядке. Roster: hamming, munger, fermi, bezos.
2. Пауза правила 2: был ёмкостный отрез — назначение показано
   владельцу; тот подтвердил лимит (мог поднять до пяти — suntzu
   вернулся бы в состав).
3. Такт 1 — четверо параллельно, изолированно.
4. Отчёты: `munger` — «провал гарантирован: cutover раньше поддержки
   таблиц» + отброшенные вероятностные → строка «premortem»;
   `fermi` — «решает фактор: пропускная способность шлюза — замер
   недоступен до старта → suntzu (разведка иными средствами)»;
   `bezos` — «дверь односторонняя, процесс соразмерен, сузить
   дизайном: canary». Такт 2 (лимит 2): `premortem-reviewer` на
   вероятностные кандидаты + `suntzu` с находкой fermi — он в
   такте 1 не работал, а если бы и работал, передачу это не
   закрыло бы: изолированный участник находки не видел. Ёмкостно
   отрезанный suntzu вернулся передачей — из «непокрыто» выходит.
5. `review-arbiter` сводит шесть отчётов: конфликт «suntzu:
   выступать при разведке» против «munger: блок до механизма»
   разрешается в пользу блока (недоказанное отсеяно, блок
   конкретнее), вердикт один: «НЕ НАЧИНАТЬ — до закрытия убийцы
   таблиц и canary-механизма; непокрыто: нагрузочный замер шлюза —
   отдельным вызовом по решению владельца. Раунд 1 из 2».

## Портируемость

Всё — markdown: составы и протокол читаемы человеком и любым
harness. Проверено переносом: `goldratt` отработал в opencode на
чужой модели без единой правки тела — менялся только frontmatter
([`docs/portability-opencode.md`](docs/portability-opencode.md)).
В harness без субагентов roster исполняется
последовательными одиночными вызовами; изоляция — **свежей сессией
на каждого ревьюера** (в opencode это отдельный `run` без
`--continue`): вызовы внутри одной сессии изоляции не дают — второй
ревьюер видит отчёт первого и вырождается в его копию; свод —
последним вызовом
`review-arbiter` со всеми отчётами во входе. Teammate-протокол
внутри спеки `review-arbiter` (каталог отчётов
`.claude/review/reports/`, право допроса ревьюеров, синхронизация
раундов) — опция богатого harness: в портируемой модели арбитр
получает все отчёты одним входом, а вместо допроса помечает
недостающее «непокрыто». Недоступен сам арбитр — свод исполняет
вызывающий по его спеке как чек-листу, с пометкой «свод вручную».
