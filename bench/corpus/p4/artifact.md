# План backend-команды на Q4

## Приоритет квартала

Данные саппорта однозначны: **40% тикетов — про медленный дашборд**,
это крупнейший источник боли. Фокус квартала — производительность
дашборда. BUG-101 (12% тикетов) берём вторым приоритетом.

## Задачи

1. **Оптимизация загрузки дашборда** — переписать агрегирующие
   запросы, добавить материализованные представления. Цель — ответ
   API дашборда < 200 мс на p95. Оценка: 4 недели, 2 инженера
   (8 инженеро-недель).
2. **Кэш агрегатов дашборда в Redis** — снять нагрузку с БД,
   ускорить дашборд. Ожидаемый эффект — вернуть тех же клиентов, что
   и задача 1. Оценка: 3 недели, 1 инженер.
3. **BUG-101: фикс потери вложений при экспорте** — переписать
   сборку архива. Объём работ пока не оценён точно, риск высокий;
   закладываем 6 недель, 1 инженер, но сначала — задача 4.
4. **BUG-101: разведка перед фиксом** — воспроизвести баг, найти
   класс причин, разбить на подзадачи. 1 неделя, 1 инженер. По
   итогам уточним оценку задачи 3.
5. **Отключить автосохранение черновиков проектов** — фича пишет в
   БД каждые 10 секунд, это половина write-нагрузки. Отключение
   разгрузит БД и ускорит в том числе дашборд. 1 неделя.
6. **Удалить legacy-экспорт в CSV** — старый форматтер, код мешает
   рефакторингу экспортного модуля. 1 неделя.
7. **Апгрейд ORM** — текущая версия снята с поддержки. 3 недели,
   1 инженер.

## Бюджет

Итого работы укладываются в квартал: команда из трёх человек за
13 недель закрывает список с запасом.

## Критерий успеха

- p95 ответа API дашборда < 200 мс;
- все 7 задач закрыты;
- деплой без инцидентов.
