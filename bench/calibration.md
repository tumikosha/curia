# Результаты калибровки корпуса

Прогон baseline (**один вызов Fable 5**, промпт «найди все дефекты»,
изолированный вход, вслепую) против ключей. Цель калибровки — до
дорогого полного прогона проверить, различает ли корпус системы.

## Главный вывод

**Один вызов сильной модели насыщает recall на посевном корпусе.**
На лёгкой версии (одна явная «рыба» в артефакте) — потолок берётся
одним проходом. На жёсткой версии (6 доказуемых дефектов разного
класса, громкий перетягивает внимание, тихие зарыты, плюс ловушка
точности) baseline держит 17/18 суммарно по трём прогонам и ни разу
не покупается на ловушку.

Гипотеза «curia даёт отрыв по полноте» посевным бенчмарком **не
подтверждается**. Причина методологическая: посев by construction
делает дефект findable — а сильная модель за один проход findable
дефекты и находит. Recall на findable дефектах — не та ось, где
многоагентный каталог линз может отличаться.

## Что осталось различающего

Единственный наблюдаемый разброс — **дисперсия на тонком дефекте**:
b2 (прокси-метрика: критерий «API < 200 мс» не покрывает жалобу
«загрузка 8–12 с») теряется 1 раз из 3. Отсюда — если у curia есть
измеримое преимущество, оно в **гарантии (worst-case recall под N
прогонов)**, а не в среднем. Выделенный судья под класс берёт такой
дефект детерминированно; один вызов — вероятностно. Но выигрыш
масштаба «полдефекта из шести» ценой ~10 вызовов агентов окупается
только там, где цена пропуска высока (необратимое решение).

## Точность baseline

Побочно: один вызов даёт **высокую точность**, не шум. Unseeded-
находки, которых не было в ключах, — реальные дефекты (неверный
знаменатель бюджета 39 vs 33; отсутствие расчёта выручки при данных
для него; отсутствие календаря зависимостей). Гипотеза «baseline
берёт recall ценой ложных срабатываний» тоже не подтверждается.

## Рекомендация по метрике

Recall-на-посеве показывает паритет — это публикуемый отрицательный
результат. Для честного теста ценности каталога сменить ось на одну
из:

1. **Гарантия**: worst-case recall из N прогонов, не средний. Где
   curia детерминирует то, что один вызов теряет вероятностно.
2. **Отказные входы**: артефакты, где верный ответ — «не делать /
   не начинать / вернуть автору». Один вызов склонен всегда находить,
   что чинить; suntzu/bezos/munger заточены на no-go. Посев здесь —
   не «дефект в тексте», а «решение не должно быть принято».
3. **Вопрос, который иначе не задан**: вход без явных дефектов, где
   структурная слабость видна только под конкретной линзой
   (Голдратт — работа вне ограничения; Хэмминг — важнейшая задача не
   в портфеле). Тут баз-лайн не знает, что искать, а судья обязан
   спросить.

Ось 1 переиспользует текущий корпус как есть (гнать N прогонов,
брать минимум). Оси 2–3 требуют других артефактов.
