# Бенчмарк ревью-систем: корпус с посеянными дефектами

Корпус для сравнения Curia с другими подходами к ревью: один вызов
модели «сделай ревью», сторонние код-боты, ручное ревью. Ground truth —
посеянные дефекты известного класса; мнение судьи о чужом отчёте
ground truth не является.

## Состав

10 артефактов, каждый в своём каталоге `corpus/<id>/`:
`task.md` — исходное задание дословно, остальные файлы — артефакт.

**Мыслительные (p1–p5)** — жанры, в которых у код-ботов нет категорий:

| id | жанр | посеянные классы дефектов |
|----|------|---------------------------|
| p1 | план миграции с числами | арифметика не сходится; предпосылка против ТЗ; необратимый шаг без отката |
| p2 | постмортем | фикс симптома вместо корня; молча исчезнувший контрсигнал; звено из пересказа |
| p3 | RFC «строить или купить» | счёт доводов вместо веса; нет критерия победы; «дешевле» без чисел |
| p4 | квартальный план | важнейшая задача не в портфеле; работа вне ограничения; критерий меряет активность |
| p5 | решение о процессе релизов | компромисс вместо разрешения противоречия; цикл длиннее темпа среды; петля без наблюдения |

**Кодовые (c1–c5)** — поле, где конкурентов много:

| id | жанр | посеянные классы дефектов |
|----|------|---------------------------|
| c1 | курсорная пагинация | потеря записей на границе; целочисленное деление страниц; невалидируемый limit |
| c2 | ручки личного кабинета | IDOR; SQL-инъекция при задекларированном белом списке; секрет в логах |
| c3 | списание с баланса | check-then-act гонка; идемпотентность из ТЗ не реализована; проглоченная ошибка с ответом ok |
| c4 | кэш карточки товара | инвалидация не того ключа против SLA; N+1 |
| c5 | rate limiter | подмена задачи: глобальный вместо per-key; burst не реализован; контракт ответа нарушен |

**Жанровые (e1)** — вход под одного судью, дефекты не в исполнении:

| id | жанр | посеянные классы дефектов |
|----|------|---------------------------|
| e1 | ежедневный отчёт партнёру: воркер, кэш, cron | получателя нет — требование под отменённый контекст; кэш и лимит от старого объёма данных; автоматизация до вопроса «зачем» |

| ch1 | список сноса в сервисе биллинга: десять оград | по ограде на ветку правила вердикта `chesterton`: живая причина, мёртвая причина без отката, мусор от мержа, живой прислонившийся при мёртвой исходной причине, ненайденная причина, публичная поверхность без телеметрии, кластер, исполненный необратимый снос |

| g1 | онбординг корпоративных клиентов: предложение нанять и докупить | ограничение — правило, а не ресурс; расширение до выжимания; мешающий KPI загрузки; улучшения вне ограничения |
| g2 | тот же поток без замеров | мера результата не названа — проверяет ветку отказа |

В g1 две ловушки: улучшения вне ограничения, очевидно полезные, и
работа на ограничении, которая выглядит ненужной, — приманка выйти
в юрисдикцию `elon`.

В ch1 ловушка — комментарий «не трогать, так исторически сложилось»:
приманка на поклонение ограде. Главная поведенческая проверка — свод:
при ненулевых стопах квота `elon` не считается.

В e1 своя ловушка точности: модуль, который выглядит частью
ненужного отчёта, но им пользуется живой дашборд.

В c4 есть **ловушка точности**: осознанно правильное решение
(best-effort кэш), которое шумный ревьюер пометит как дефект.

## Ключи (`truth/`)

По ключу на артефакт, в base64: `truth/<id>.md.b64`. Читать после
прогона: `base64 -d -i truth/p1.md.b64`. Кодировка — защита от
случайного заражения (grep судьи по репозиторию), не от умысла:
умышленное декодирование видно в трейсе судьи.

Ключ перечисляет blocker'ы с id (`p1-b1`), классом, местом и
формулировкой «почему blocker», плюс известный неосновной шум.

## Протокол прогона

1. Судимой системе — только `corpus/<id>/`: `task.md` как задание,
   остальное как артефакт. Ключи и этот README в её вход не идут.
2. Одна и та же модель во всех системах, где это возможно: иначе
   сравнивается модель, а не архитектура.
3. По 2 прогона на систему на артефакт — дисперсия LLM большая.
4. Отчёты обезличить (убрать имена систем и агентов), затем свести
   с ключом. Спорную находку судит арбитр на другой модели.
5. Находка вне ключа — адъюдикация: легитимная вносится в ключ как
   `unseeded` (не штрафует точность, в полноту не идёт),
   нелегитимная считается шумом.

## Метрики

- **Полнота**: найденные посеянные blocker'ы / все посеянные.
  Blocker засчитан, если отчёт называет и место, и механизм; «что-то
  не так рядом» — половина балла по решению арбитра.
- **Точность**: подтверждённые находки / все находки отчёта.
- **Цена blocker'а**: суммарные токены (или вызовы агентов) /
  подтверждённые blocker'ы. Головная метрика.
- **Wall time** на артефакт.

Считать раздельно по группам p и c: гипотеза в том, что на p-группе
разрыв с код-ботами максимален, на c-группе — паритет.
