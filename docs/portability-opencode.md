# Портируемость: прогон `goldratt` в opencode

Первый перенос агента каталога в чужой harness — шаг, который ROADMAP
называл обязательным, чтобы «портируемый каталог» перестал быть
декларацией. Прогон сделан 2026-08-30.

## Стенд

| | |
|---|---|
| harness | opencode 1.18.23 (не Claude Code) |
| модель | `opencode/nemotron-3-ultra-free` (Zen; не Claude) |
| агент | `agents.ru/goldratt.md` — тело перенесено дословно |
| стенд | временный проект с `.opencode/agent/goldratt.md` |
| запуск | `opencode run --pure --dir <стенд> --agent goldratt --model <модель> "<вход>"` |

Модель выбрана чужая намеренно: перенос между двумя реализациями
Claude ничего не доказывал бы — проверялось, держит ли процедура
агента другую модель на другом движке.

## Что пришлось поменять

**Тело агента — ни одной правки.** 196 строк процедуры, правил
вердикта, демаркации и формата перенесены дословно и отработали.
Менялся только frontmatter и способ запуска.

### Frontmatter: четыре различия

| Claude Code | opencode | почему |
|---|---|---|
| `name: goldratt` | поля нет | имя агента = имя файла |
| `tools: Read, Grep, Glob, Bash` | `tools:` объектом, ключи в нижнем регистре: `read: true`, `bash: true` | список инструментов заменён картой булевых |
| — (read-only = не перечислять пишущие) | `write: false`, `edit: false`, `patch: false` явно | по умолчанию инструменты **разрешены**: read-only требует явных запретов, иначе агент сможет писать |
| `model: inherit` | `model: <провайдер>/<модель>` | наследования тира нет; поле можно опустить (возьмётся дефолт конфига) или указать явно |
| — | `mode: primary \| subagent \| all` | новое обязательное решение, см. ниже |
| — | `temperature: 0.1` | опционально; у Claude Code такого поля нет |

### Три ловушки запуска

1. **`mode: subagent` не запускается из CLI.** `opencode run --agent X`
   работает только с `primary` или `all`; на subagent-е harness молча
   откатывается на дефолтного агента и выполняет запрос **не тем
   агентом** — тихая подмена, которую легко не заметить в выводе.
   Для CLI-прогона нужен `mode: primary` (или `all`).
2. **Дефолтная модель конфига может не существовать** — в `opencode.json`
   стояла `ollama/qwen3.6:27b`, локально её нет, прогон падал с
   `model not found`. Лечится флагом `--model`.
3. **Чужие плагины подмешивают своих агентов и правила.** В стенде
   активные плагины подставляли собственного primary-агента поверх
   запроса. Флаг `--pure` отключает внешние плагины — без него ревью
   идёт в чужой оснастке и вердикт нельзя атрибутировать агенту.

### Изоляция в чужом harness — подтверждено практикой

Раздел «Портируемость» в `TEAM.md` обещал изоляцию «порядком
вызовов». Уточнение по факту: изоляция достигается **свежей сессией
на каждого ревьюера** — в opencode это отдельный `opencode run` без
`--continue`/`--session`. Последовательные вызовы внутри одной сессии
изоляции не дают: второй ревьюер видит отчёт первого в контексте и
вырождается в его копию.

## Что получилось

**Прогон 1** — вход из `examples/goldratt-example.md` (http2md,
«перепишем парсер эффективнее», замеры парсера и стадии fetch даны
строкой входа).

Чужая модель воспроизвела процедуру целиком: строка `ПОРЯДОК: нарушен`,
все пять шагов, тип ограничения («правило»), вердикт **«работа вне
ограничения — вклад в меру ноль»**, запрет шага 4 при неисчерпанном
шаге 2, финальная пара «самое дорогое утверждение — чем опровергается»
(«замер после снятия `wait_for_timeout` и переиспользования браузера;
если мера не упадёт на ≥50% — ограничение не здесь»). Вердикт совпал
с эталонным примером каталога по существу и по форме.

Отличия в мелочах: тип ограничения назван «ресурс / правило» вместо
чистого «правило», в шаге 5 добавлена инерция — расхождения в пределах
допустимой вариации, процедурных нарушений нет.

**Прогон 2** — контрактный тест: «ускорить сборку, параллелить тесты»
без меры результата. Ответ: **ОТКАЗ — мера результата не названа**, с
перечнем того, что нужно принести (p50/p95 времени сборки, целевое
время, профиль). Дисциплина отказа пережила смену модели — это
главное, что проверялось: без неё агент на чужом движке выродился бы
в генератор советов.

## Вывод для каталога

Портируемость подтверждена на одном агенте: тело — чистый markdown,
переносится дословно; harness-специфичен только frontmatter, и дельта
укладывается в таблицу выше. Стоимость переноса остальных двадцати —
механическая правка frontmatter, тела не трогаются.

Открытое: перенос командного протокола (`TEAM.md`) целиком не
проверялся — прогонялся один агент, а не команда. Триаж, такты и свод
в opencode исполнимы вручную (роль вызывающего берёт человек), но
живого прогона команды в чужом harness пока нет.
